Deploy your API gateway on ultra low-latency microVMs that scale up when required and cost nothing when idle.

<ValueCards>
  <ValueCard title="Scale up in milliseconds during a spike" metric="scale up in < 10 ms">
    [Autoscale](/features/autoscale) adds gateway instances as traffic climbs and removes them as it subsides, [down to zero](/features/scale-to-zero) when nothing is arriving.
  </ValueCard>
  <ValueCard title="VM-level isolation" metric="own kernel per instance">
    Each gateway is a hardware-isolated microVM with its own kernel, not a process sharing a host runtime.
  </ValueCard>
  <ValueCard title="Low latency at the edge" metric="ultra-low latency">
    Millisecond cold starts, minimal memory footprints and transparent [load balancing](/features/load-balancing) within a service group results in ultra-low latency.
  </ValueCard>
</ValueCards>

## Under the hood

The platform features this use case is built on.

<FeatureTable>
  <FeatureRow title="Load balancing" href="/features/load-balancing">
    Starts as soon as multiple instances are attached to a service group.
    There's no separate load balancing instance to run.
  </FeatureRow>
  <FeatureRow title="Autoscale" href="/features/autoscale">
    Scales up during traffic spikes in milliseconds and back down once they subside.
  </FeatureRow>
  <FeatureRow title="Scale-to-zero" href="/features/scale-to-zero">
    An idle gateway isn't running, so you aren't paying for it between requests.
  </FeatureRow>
</FeatureTable>
