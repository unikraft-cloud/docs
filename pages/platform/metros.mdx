By default, at present, Unikraft Cloud supports the following metros:

| IATA code  | | Region                     |
|:-----------|-|:---------------------------|
| `dal`      | 🇺🇸 | Dallas, TX, USA         |
| `fra`      | 🇩🇪 | Frankfurt, DE           |
| `sfo`      | 🇺🇸 | San Francisco, USA      |
| `sin`      | 🇸🇬 | Singapore               |
| `was`      | 🇺🇸 | Washington DC, USA      |

You can list the metros available to your account via the CLI:

```bash
unikraft metros list
```

{/* vale off */}
:::tip[One client, every metro]
The [SDKs](/sdks/overview) treat the metros in scope as one namespace: reads
ask each of them at once and merge the answers, tagged with where they came
from, so no list of endpoints is kept in your code.

```ts
for await (const inst of ukc.instances.list()) console.log(inst.metro, inst.name);
```

Name a metro — `ukc.metro("fra")`, or `UKC_METRO` — to pin a client to one.
See the [JavaScript](/sdks/js) and [Python](/sdks/python) SDKs.
The [Go SDK](/sdks/go) targets one metro per client, so group results across metros yourself.
:::
{/* vale on */}

Old metros such as `fra0` are nearing end of life, and aren't available for new deployments.

Unikraft Cloud continues to add new locations worldwide so you can provision services close to your users.
If there's a metro location you'd need, please contact Unikraft Cloud on [Discord](https://unikraft.com/discord) or write to [support@unikraft.cloud](mailto:support@unikraft.cloud).

## Intra-data center provider connectivity

For more information on how Unikraft Cloud connects metros together, and for more information about how to reduce in/egress costs with existing deployments at other IaaS providers, please [get in touch](mailto:support@unikraft.cloud).

## Self-hosted/on-premise metros

If you require running solutions in-house or on-premise, either for SOC/ISO/HIPPA compliance or for other security, performance or cost-saving reasons, please [get in contact](mailto:support@kunikraft.cloud) for more details.

## Usage

You can set the metro you wish to use by setting the `--metro` flag.
Use the IATA code descriptor to target the specific metro.
For example with `fra`:

```bash
unikraft run --metro fra \
  -p 443:8080/http+tls \
  --image <my-org>/nginx:latest
```

For on-premise or enterprise users, you need to set the API endpoint of the metro you wish to use.
To do this, define a custom [profile](/tutorials/kraftkit-to-unikraft#profile-management) and give an identifier to the metro you wish to use:

```bash
unikraft profile use <custom-profile>
unikraft run --metro <custom-metro> ...
```
